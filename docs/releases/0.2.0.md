# Voxriva 0.2.0 source prerelease

## Email layouts and authoring

- Create multiple reusable layouts with their own languages, branches,
  publications and deployments. Each HTML or plain-text layout format
  places the letter body at one structural slot. Letters contribute their
  own delivery subject, body and parameters.
- Let a template follow the active layout in its environment or pin a
  specific published layout version. Layout rollout and rollback affect
  subsequent acceptance for active references. Notifications already accepted
  retain the exact template and layout versions for delivery and retries.
- In **Draft editor**, choose **Template version** beside **Editing language**
  to preview a published snapshot. **Current draft** restores unsaved work.
  **Layout version** separately controls the layout used in draft preview.
- Voxriva MCP supports layout discovery using `is_layout`, scoped layout
  selection and preview against an explicit project and environment.
  Publication and deployment take place in the dashboard.

See the [workspace guide](../workspace-guide.md#author-email-layouts) and
[layout resolution](../journeys/lifecycle.md#layout-resolution).

## Evaluate from source

Check out `v0.2.0` or extract the release archive after verifying its checksum.
From the source root with Python 3.10+ and Docker Compose v2, run:

```sh
python3 scripts/example.py up --layout-preview --name northstar-layouts
```

Open the printed editor URL using the access file printed by the launcher.
See [Northstar evaluation](../evaluate.md#inspect-northstar-email-layouts).

## Upgrade

Back up PostgreSQL and the complete keyring before upgrading. Build matching
API and MCP images from this source for your installation. Use the coordinated
[upgrade and restore runbook](../../PRODUCTION.md) to drain delivery, apply
Alembic migration `0014_email_layouts`, and start matching API, relay, worker
and MCP versions. The migration adds a layout discriminator to templates and
an optional layout version reference to notifications. Existing templates
and queued notifications continue with their original template version.
A rollback after running the migration should follow the backup and restore
procedure in the runbook.

## Verification and artifacts

Coverage includes Chromium scenarios for layout composition in preview and
Mailpit, activation and rollback, queued version pinning, and Draft Editor
version switching. The MCP smoke checks layout discovery and scoped preview
over Streamable HTTP against PostgreSQL. The source prerelease workflow runs
full CI on the tagged revision before publication.

The GitHub prerelease contains source archives, release notes, workflow
provenance and SHA-256 checksums. The application, dashboard and Python SDK
source versions are 0.2.0. Build the images and SDK locally from this source.
See [release status](../release-status.md) for the separately distributed
0.1.1 artifacts and operating scope.
