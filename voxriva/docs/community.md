# Contribute and get help

Voxriva is developed in [AlexIvanchyk/Voxriva](https://github.com/AlexIvanchyk/Voxriva).
Use GitHub to report reproducible bugs, propose improvements and ask questions.
For a working local installation, start with [the quickstart](quickstart.md).

| You want to… | Start here |
| --- | --- |
| Report a bug or propose a feature | [GitHub issues](https://github.com/AlexIvanchyk/Voxriva/issues) |
| Ask an integration or self-hosting question | [Support guide](https://github.com/AlexIvanchyk/Voxriva/blob/HEAD/SUPPORT.md) |
| Make a code or documentation contribution | [Contributing guide](https://github.com/AlexIvanchyk/Voxriva/blob/HEAD/CONTRIBUTING.md), [development](development.md) |
| Report a potential vulnerability | [Security policy](https://github.com/AlexIvanchyk/Voxriva/blob/HEAD/SECURITY.md) |
| Understand community expectations | [Code of Conduct](https://github.com/AlexIvanchyk/Voxriva/blob/HEAD/CODE_OF_CONDUCT.md) |
| Review release changes and current commitments | [Changelog](https://github.com/AlexIvanchyk/Voxriva/blob/HEAD/CHANGELOG.md), [release status](release-status.md) |

When opening an issue, include the source revision/version, installation mode,
minimal fictional reproduction, expected behavior and actual result. Remove
credentials, real recipients, device tokens and runtime message data from logs
and screenshots. Support is community-based, with no guaranteed response time.

The repository owner is [@AlexIvanchyk](https://github.com/AlexIvanchyk).
Maintainers review contributions and coordinate releases through GitHub. A
source contribution does not publish an image or deploy a website; release
prerequisites are tracked separately in [release status](release-status.md).
