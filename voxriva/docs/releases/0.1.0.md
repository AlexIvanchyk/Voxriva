# Voxriva 0.1.0 source prerelease

This first prerelease distributes the Voxriva source code and operator
documentation. It is intended for local evaluation and review before a production
installation. Container images and a PyPI package are not included in this source
release.

## Included

- A web dashboard for projects, environments, notification templates, languages,
  immutable published versions and deployment history.
- Email and push delivery through SMTP, Amazon SES and Firebase Cloud Messaging,
  with idempotency, retries, scoped delivery status and an operational history.
- A frozen Delivery v1 HTTP contract and a typed synchronous/asynchronous Python
  SDK, built from the same source version.
- Optional MCP authoring, scoped management credentials and authenticator MFA.
- An isolated local email example, production Compose configuration, migrations,
  and coordinated database/keyring backup and restore tools.
- CI for documentation, backend, frontend, dependency audits and isolated runtime
  scenarios, plus separate source-release, GHCR and documentation workflows.

## Evaluate the source

Use Python 3.10+ and a running Docker Engine with Compose v2:

```sh
git clone https://github.com/AlexIvanchyk/Voxriva.git
cd Voxriva
git checkout v0.1.0
cd voxriva
python3 scripts/example.py
```

The example creates a fictional workspace and local Mailpit inbox. Follow the
[quickstart](../quickstart.md) for the first delivery and scoped cleanup. For
source archives, verify `SHA256SUMS`, extract the archive and run the launcher
from its `voxriva/` directory.

## Production and distribution boundaries

The application, frontend and bundled Python SDK metadata are `0.1.0`. This is a
prerelease with no general cross-version compatibility or capacity guarantee.
Production tooling targets one Linux Docker host with Engine 28+, Compose v2,
PostgreSQL 17 and operator-managed DNS/TLS. Read the
[production runbook](../../PRODUCTION.md) before using real data.

Voxriva's own code and documentation are MIT-licensed. Dependencies retain their
upstream terms. Public container distribution still requires the artifact-specific
notices and redistribution review recorded in
[third-party notices](../../THIRD_PARTY_NOTICES.md); dependency scans alone do not
complete that review. GHCR publishing retains its separate explicit approval and
exact-image checks.

Documentation Pages is deployed separately. On GitHub Free, this private
repository must first be made public by its owner before Pages can be enabled.
The presence of a workflow or this source release does not establish a successful
Pages deployment.
