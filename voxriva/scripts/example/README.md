# First-email example tooling

From `voxriva/`: `python3 scripts/example.py`. Requires Docker/Compose v2 and
Python 3.10+ on macOS/Linux; no pip/npm install is needed on the host. See
[the first-email guide](../../docs/quickstart.md) for ports, private login,
integration, repeat behavior and scoped stop/removal.

This launcher owns only `voxriva-example-<name>` projects and the generated
`output/example/<name>/` directory. It checks every Compose container, volume and
network against a random owner label saved in mode-0600 state before startup or
cleanup. It never accepts an arbitrary target URL/project name or deletes a
user's existing workspace. Explicit ports must be free; automatic selection is
persisted. The default collector is disabled so this example needs no mounted
Docker socket. Only app and Mailpit web ports are exposed, on loopback.

`fixture.json` is a curated, fictional dataset: project/environment names and a
sample request. `../demo/fixtures.py` supplies the same original Northstar EN/UK
email content, typed schemas, defaults and preview scenarios used by the richer
demo. `../demo/assets/` supplies versioned original raster assets, generated by
`../demo/assets.py`. No database export, installation IDs, encrypted blobs or
issued credentials belong in these source fixtures. The first-email path uses
only English, one environment and one successful local SMTP send; it does not
automatically enroll MFA or stage failures.

`seed.py` uses supported administration and Delivery HTTP APIs. Initial account
creation calls the existing bootstrap domain service in the isolated API container
with credentials on stdin; there is no SQL fixture bypass. A separate HTTP client
with no dashboard cookie validates, sends and polls using the environment key.
Receipt verification matches the worker's SMTP message ID and exact image bytes.
Raw MIME and keys are not printed or saved in public logs.

The image is built from the current source with its own tag, not pulled from an
invented registry. `compose.yaml` is an overlay on the canonical local stack;
health checks, migrations and the normal workers remain the application's own.
Build/start diagnostics are private `compose.log`; bootstrap output is discarded.
A failed build/start preserves state and supports rerunning. An interruption
between a committed API operation and saving its result is reconciled from named
resources; notification acceptance also has a stable idempotency key. A lost
one-time key response can leave an unused key; it is not silently revoked.

Run the orchestration safety checks with:

```sh
python3 -m unittest discover -s scripts/example -p 'test_*.py'
```

A meaningful end-to-end check is a fresh named run, a repeat (same notification
and receipt, no new messages), stop/resume, and removal of that name. Never run
the richer demo seed against a first-email example: it intentionally requires an
empty, separately prepared installation.
